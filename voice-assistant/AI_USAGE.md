 AI Usage Log

## Summary

This project does not use a large language model as its runtime decision engine. The core decision-making logic is implemented in rule-based Python code in `backend/app/nlu.py` and `backend/app/dialogue.py`. Appointment scheduling, token allocation, and conversation state are handled deterministically and are designed to be testable.

AI-assisted tools were used during development to support design, implementation, review, and verification. The final booking logic runs through the application's Python code rather than an LLM-driven workflow.

## Tools Used

- GPT (free version) for development assistance.
- Student Bundle: 20.2 credits used.
- Copilot-style coding assistance in VS Code / Copilot SDK, where applicable.
- Targeted file-reading and search operations to inspect the project structure and relevant files.
- Python test execution and validation using `pytest`.

## How AI Assistance Was Used

AI assistance supported the development process by helping with:

- Scaffolding the initial project structure and file layout.
- Clarifying the children's clinic appointment use case and conversation state transitions.
- Generating and refining regex-based parsing logic for dates, child details, and appointment intents.
- Identifying edge cases such as closed days, invalid dates, bare numbers, and correction flows.
- Reviewing the code for completeness and consistency with the test suite.

## AI Assistance in Logic Design and Decision-Making

AI was used as a development aid to reason about, design, review, and refine the application's rule-based logic. This included natural-language parsing, dialogue-state transitions, appointment booking workflows, date validation, and handling unusual or ambiguous inputs.

AI suggestions helped explore possible approaches and identify cases that needed explicit handling or testing. The suggestions were reviewed during implementation, and the relevant behavior was implemented in the application's Python code.

AI assistance did not become the application's runtime decision engine. During operation, the application makes decisions using its implemented rules, validation logic, database checks, and conversation-state transitions.

## Where AI Assistance Was Most Useful

The most useful contributions were:

- Developing the initial NLU grammar for natural-language inputs.
- Supporting the design of the state machine for booking, checking, rescheduling, and cancelling appointments.
- Suggesting call scenarios to test, including invalid dates, confirmation steps, corrections, and concurrent token requests.
- Helping review implementation completeness against the test suite.

## Where AI Was Not Used at Runtime

The decision engine was not delegated to an external large language model.

When a caller interacts with the application, it does not call GPT, Claude, Gemini, or another external LLM API to decide what action to take. The runtime process is:

1. Parse the caller's text.
2. Identify the supported intent using implemented rules.
3. Validate appointment details.
4. Check relevant database records and scheduling rules.
5. Update conversation state or appointment data as appropriate.
6. Return a deterministic response.

This was a deliberate project constraint and is part of the system's design.
